1. Project Overview
Codexia is an Android reading tracker built with Jetpack Compose and Kotlin. It follows an offline-first architecture, allowing users to manually log, annotate, and visualize their reading journey across web comics and light novels. The app is governed by the "Arcane Grimoire" design language: dark, cozy, and intimate.

3.1 Progress Logger (SeriesDetailScreen)

Current State

OutlinedTextField for Notes has no mutableStateOf.

Required Changes
Add local state: var chapterInput by remember { mutableStateOf("") }
Add local state: var notesInput by remember { mutableStateOf("") }

3.2 Room Database Integration
All persistent data currently lives in DummyData.kt. This must be replaced with a Room database.

Implementation Steps
Create AppDatabase.kt extending RoomDatabase, listing all entity classes.
Create @Entity data classes (Series, Shelf, Genre, SeriesGenreCrossRef, LogEntry) matching the schema in section 2.2.
Create @Dao interfaces for each entity with standard CRUD plus Flow-returning queries.
Create Repository classes that wrap Dao calls and expose Flow<List<T>> to ViewModels.
Create ViewModels (LibraryViewModel, SeriesDetailViewModel, InsightsViewModel) using StateFlow and viewModelScope.
Wire ViewModels to Composables via viewModel() or hiltViewModel() and collectAsStateWithLifecycle().
Seed default shelves ("Webcomics", "Light Novels", "Favorites") in a RoomDatabase.Callback on first creation.

Dependency

3.3 Library Search & Shelf Filtering (LibraryScreen)
The search bar and shelf tabs currently have no filtering logic.

Search

Derive a filtered series list using combine(allSeries, searchQuery) { series, query -> series.filter { ... } }.
Match against title (case-insensitive) and author fields.
Display a "No results found" empty state when the filtered list is empty.

Shelf Tab Filtering
Expose selectedShelf: MutableStateFlow<String> from ViewModel.

3.7 Cover Image Picker (AddEditSeriesScreen)
The "From Gallery" and "Search Online" buttons exist but have no logic.

Gallery Pick
Register a launcher: val launcher = rememberLauncherForActivityResult(ActivityResultContracts.GetContent()) { uri -> coverUri = uri }
On "From Gallery" click: launcher.launch("image/*")
Display the selected image using AsyncImage from Coil with a placeholder.
Save the URI string to the Series.coverPath field in the database.

Online Search
On "Search Online" click, navigate to a new CoverSearchScreen route, passing the series title as a query parameter.
CoverSearchScreen shows a search bar pre-filled with the title and a grid of results from an image API (e.g., Google Custom Search JSON API or Bing Image Search).
Tapping a result downloads the image to internal storage, saves the local path to coverPath, and navigates back.
Note: API key management must be handled securely via BuildConfig or an environment variable.

3.9 Edit Mode (AddEditSeriesScreen)
The Edit button in SeriesDetailScreen navigates to a blank AddEditSeriesScreen. It should pre-populate all fields with the series data.

Navigation Change
Change the route to: navController.navigate("addEditSeries/${series.id}")
Register in MainActivity NavHost: composable("addEditSeries/{seriesId?}") { ... }
seriesId is optional ù null means "add new", non-null means "edit existing".

ViewModel
AddEditSeriesViewModel takes an optional seriesId parameter.
If seriesId is non-null, load the series from the repository and populate form state fields.

3.10 Dynamic Greeting (HomeScreen)
The greeting is hardcoded as "Good Evening, Acin." It should reflect the actual time of day and eventually the actual user name.

Time-Based Greeting
fun getGreeting(): String {
    val hour = Calendar.getInstance().get(Calendar.HOUR_OF_DAY)
    return when (hour) {
        in 5..11  -> "Good Morning"
        in 12..16 -> "Good Afternoon"
        in 17..20 -> "Good Evening"
        else      -> "Good Night"
    }
}

User name should come from a UserPreferences datastore key (or Room users table). Default to "Reader" if not set.
Recompute the greeting on each HomeScreen recomposition or via a remembered derivedStateOf.

4. Insights Screen Enhancements

4.1 Reading Streak Tracker
The MotivationalBanner currently shows a hardcoded string. It must reflect an actual streak computed from the database.

Streak Calculation Logic
Query all LogEntry timestamps ordered by date descending.
Group by calendar day (yyyy-MM-dd format).
Walk backward from today: if today has at least one entry, streak starts at 1. Each consecutive previous day with an entry increments the streak.
Store currentStreak: Int in InsightsViewModel as a StateFlow derived from the log entries Flow.

UI
MotivationalBanner should show: "You've read for X days in a row ù keep it up!" or a distinct message at streak milestones (7, 30, 100 days).
If streak is 0, show: "Start reading today to begin your streak!"

4.2 Monthly Chapter Count Chart
A monthly chart is needed alongside the existing weekly activity chart.

Data
Query: SELECT strftime('%Y-%m', timestamp) as month, COUNT(*) as entries FROM log_entries GROUP BY month ORDER BY month DESC LIMIT 6
Expose as a Flow<List<MonthlyCount>> from the repository.

UI
Add a MonthlyActivityChart composable below WeeklyActivityChart using the same bar chart pattern.
X-axis labels: abbreviated month names ("Jan", "Feb", etc.).
Y-axis: scale bars relative to the maximum count in the dataset.

4.3 Date Range Filter
The Insights screen should allow filtering stats by a date range.

UI
Add a FilterChip row below the top bar: "This Week", "This Month", "This Year", "All Time".
Selected chip is highlighted with primary color.
Expose selectedRange: MutableStateFlow<DateRange> from InsightsViewModel.
All queries (streak, charts, total chapters, genre distribution) must filter by the selected range.


5. UX & Polish

5.1 Swipe-to-Delete Log History Items
Log entries currently only support deletion via an explicit button. Swipe-to-delete should be added.

Implementation
Wrap LogHistoryItem in a SwipeToDismiss composable (androidx.compose.material3).
Reveal a red delete background with a DeleteForever icon on swipe.
On dismiss: call onDelete() ù which already includes Snackbar undo logic.
Threshold: DismissValue.DismissedToStart (left swipe only).

Code Pattern
val dismissState = rememberSwipeToDismissBoxState()
SwipeToDismissBox(
    state = dismissState,
    backgroundContent = { DeleteBackground() },
    content = { LogHistoryItem(...) }
)
LaunchedEffect(dismissState.currentValue) {
    if (dismissState.currentValue == SwipeToDismissBoxValue.EndToStart) {
        onDelete()
    }
}
